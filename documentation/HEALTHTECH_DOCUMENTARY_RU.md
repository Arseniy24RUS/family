# Документальная экспертиза проекта «Новые технологии сбережения здоровья»

Этот документ описывает происхождение материалов, правила расчёта и воспроизведение документальной части модуля `health_technologies` в накопительном выпуске `2.4.0-healthtech.1`. Дата подготовки — 29 октября 2026 года. Авторская экспертиза относится к состоянию источников на 28 октября 2026 года, шесть паспортов нового проекта — к публикациям от 16 октября 2026 года.

Исходный отчёт, извлечённые паспортные планы и независимые расчёты имеют разные признаки происхождения. Обновление числовых публикаций ЕМИСС не переписывает авторский текст, прежнюю формулу или иллюстрацию. Текущие статистические панели и правила их обновления описаны отдельно в [HEALTHTECH_DATA_AND_REFRESH_RU.md](HEALTHTECH_DATA_AND_REFRESH_RU.md).

## 2. Полный авторский отчёт, формулы, рисунки и сноски

Исходный DOCX имеет размер 2 522 835 байт и SHA-256:

```text
49a0b61d96a414e72d22ededb26e6690fd45a5e17424135617b7bb9079fd8913
```

Документ отрендерен в 105 страниц для проверки пагинации. В `coverage_manifest.json` зафиксированы 317 содержательных блоков, распределённых по 21 странице платформы: пропусков и повторного назначения блоков нет. Титульные и согласовательные формы, оглавление и пустые абзацы сохраняются в исходном DOCX и полной текстовой выгрузке; они отдельно отмечены в манифесте покрытия.

Опубликованы 15 таблиц, 14 исходных рисунков, 142 сноски и пять формул. Каждый рисунок сохраняет исходные байты и собственный SHA-256. Авторские изображения не перекрашиваются под тему сайта. Интерактивные графики используют отдельно опубликованные числовые входы и могут иметь собственную тему.

Формулы TF-IDF, нормировки L2 и косинусного сходства сверены с отрендеренной страницей 69; формулы ICER и бюджетного воздействия — со страницами 94 и 95. Сохраняются исходное представление OMML, доступная текстовая запись, LaTeX и подтверждённая страница. Формулы ICER и бюджетного воздействия представлены как методические конструкции автора: отсутствие исходных данных о стоимости и эффективности не заменяется вымышленным числовым расчётом.

Все 142 сноски имеют ссылки на исходные блоки. В том числе восстановлены 23 табличные ссылки, расположенные внутри ячеек Word. Контракт таблицы содержит:

- `headerSourceIds` — ссылки в ячейках шапки;
- `cellSourceIds` — ссылки по строкам и ячейкам массива `rows`, без шапки;
- `sourceIds` — общий перечень источников таблицы;
- `sourceBlock` — исходный блок DOCX; обратные ссылки находятся в `sources[].source_blocks`.

Номера этих сносок включены и в полную Markdown-версию. CSV таблиц предназначены для работы с данными; точные связи ячеек со сносками находятся в JSON и DOCX. В `expertise.json` находятся 143 записи источников: сам отчёт и 142 сноски. Для 256 опубликованных блоков определены страницы по сохранённому рендеру. Локаторы без уверенного совпадения не получают вымышленного номера страницы.

Отчёт извлекается скриптом `extract_healthtech_report.py`, а `build_healthtech_expertise.py` применяет редакционную карту `inputs/healthtech/report/editorial_config.json`. Карта привязана к SHA-256 исходного DOCX. Сборка другого отчёта с прежней картой останавливается на проверке контрольной суммы.

## 3. Целевые значения и связь с реестром показателей

Планы извлекаются из карточек шести паспортов и публикуются в `public/data/projects/health_technologies/targets.json`. Матрица содержит 21 показатель × 6 лет, 2025–2030: 126 ячеек, из них 118 числовых и восемь отсутствующих. Отсутствие значения сохраняется как `null`, исходный ноль — как число `0`.

Сопоставление номера карточки паспорта с кодом каталога ЕМИСС задаёт проверенная карта `target_mapping.json`. Порядок карточек в этих двух источниках различается, поэтому соединение по порядковому номеру не применяется. Для каждой строки сохранены код показателя, исходное и реестровое название, единица, редакция, документ, URL, SHA-256 и XPath карточки. Для каждой годовой ячейки дополнительно доступны исходный текст, точное десятичное представление и XPath значения. У карточки `2.14.С5.3` подтверждённого номера источника ЕМИСС нет: `source_id` остаётся `null`.

Паспортные цели сами по себе не подтверждают наличие сопоставимого наблюдения. В статистическом модуле единственное допустимое арифметическое сопоставление самостоятельного годового факта с планом в этом выпуске относится к № 62986 за 2025 год. Оно не обозначается формальной оценкой выполнения: `formal_attainment_eligible=false`. Семантическая несогласованность единицы № 62985 и изменения методики № 63059 сохраняются как ограничения. Подробные основания приведены в документе о данных и обновлении. Название выгрузки `targets_all_years.csv` означает все извлечённые годовые значения выбранных редакций; это не база всех исторических редакций паспортов.

## 4. Две финансовые рамки

### Паспортный план на 2025–2030 годы

Паспортные суммы заданы в **тысячах рублей**. Для точного сложения используется `Decimal`, исходное десятичное представление сохраняется в `amount_decimal`. Перевод в миллиарды рублей выполняется делением на 1 000 000. Сумма опубликованных распределений пяти ФП составляет **16 213 442,40 тыс. руб.**, то есть **16,2134424 млрд руб.** Она совпадает с суммой опубликованных годовых строк национального паспорта.

| ФП | Опубликованная сумма, тыс. руб. |
|---|---:|
| С1 | 5 090 960,80 |
| С2 | 3 248 601,30 |
| С3 | 3 069 567,60 |
| С4 | 1 848 844,90 |
| С5 | 2 955 467,80 |
| Итого | 16 213 442,40 |

В сетке пяти ФП и шести лет опубликованы 22 значения; восемь ячеек отсутствуют. В 2029 и 2030 годах в выбранных редакциях раскрыто только по 92 200 тыс. руб. для С1. Прочие отсутствующие значения не устанавливают нулевого финансирования этих ФП. Поэтому 16,2134424 млрд руб. характеризуют видимое распределение выбранных паспортов, а не доказанный полный объём потребности или всех будущих ассигнований.

Проверка `reconciliation` сопоставляет сумму видимых строк ФП с национальной строкой отдельно по каждому году. Нулевой остаток такой сверки не устраняет неполноту горизонта. Доли ФП и концентрация вычислены в пределах опубликованного распределения и имеют тот же знаменатель.

Детализация по результатам находится отдельно в `resultYears` и `resultSums`. Числовые строки финансирования раскрыты для 15 различных карточек результатов; всего карточек результатов в сети 28. Суммы уровня результатов проверены против соответствующего ФП и не добавляются повторно к общему финансовому итогу. Отсутствие финансовой строки у результата не заменяется утверждением о его нулевой стоимости.

### Роспись 2026 года и внесённый проект бюджета на 2027–2029 годы

Вторая рамка взята из таблицы 4.1.15 [пояснительной записки, опубликованной в системе ГАРАНТ](https://base.garant.ru/411685865/). Сохранены полный HTML, SHA-256 и точный XPath таблицы. ## 5. Идентичность карточек и границы документальной сети

У исходного HTML повторяются некоторые атрибуты `id`. Например, `fp_307:passport-result-37` встречается у трёх разных результатов; у других повторяющихся карточек также различаются заголовки и XPath. Удаление таких повторов потеряло бы содержательные результаты, а объединение финансов по исходному атрибуту `id` смешало бы суммы разных карточек.

Для узла и результата используется составной идентификатор:

```text
document_id:source_card_id:SHA256(full_XPath)[0:16]
```

Исходный атрибут остаётся в `source_card_id`, полный DOM-адрес — в `source_locator`. Стабильность этого идентификатора относится к закреплённой версии HTML. При смене редакции или структуры HTML соответствие между версиями требует отдельной проверки. Все ссылки на результаты в весах, кандидатах и финансовых строках используют составной ID; финансовые строки дополнительно сохраняют `source_result_locator` и `source_result_card_id`.

После проверки сеть содержит 62 уникальных узла, в том числе 28 различных карточек результатов и 21 карточку показателей. Остальные узлы представляют задачи. Сохранены 69 опубликованных числовых записей влияния. Для них нельзя однозначно определить адресуемый показатель: `indicator_node_id` равен `null`, статус — `unresolved_target_indicator`. Числовое поле без подтверждённой единицы не объявляется процентом причинного вклада.

Подтверждённых прямых рёбер в этой версии **ноль**: массивы `reviewedEdges` и `directLinks` пусты. Отдельно опубликованы 83 уникальных сочетания результатов и показателей внутри соответствующего ФП и их лексическое сходство. Совместимость с общим контрактом сохраняет имя `sharedTaskPairs`, однако точный класс каждого элемента — `same_federal_project_candidate`. Это означает принадлежность одному ФП, а не установленную общую задачу. Косинус помогает выбрать пару текстов для содержательной проверки; он не создаёт причинную связь и не заменяет разрешение исходного веса.

## 6. Независимый текстовый анализ и отличие от авторского расчёта

В содержательный профиль паспорта включены цель, задачи, названия и характеристики результатов, названия показателей. Бюджетные таблицы, должности, контрольные точки и календарные планы исключены. Совпадающий нормализованный фрагмент внутри документа учитывается один раз. Каждая сохранённая единица текста содержит исходный документ и XPath.

Параметры опубликованы в `text_parameters.json`:

- приведение к нижнему регистру и замена «ё» на «е»;
- токенизация выражением `[а-яёa-z]{2,}(?:-[а-яёa-z]{2,})?`;
- 120 опубликованных стоп-слов, отдельные слова и биграммы;
- биграммы только внутри содержательного поля, без перехода через границы полей;
- логарифмическая частота, сглаженный IDF, нормировка L2, `min_df=1`, `max_df=0.98`, без ограничения числа признаков;
- вектор проекта — среднее нормированных векторов его документов, затем повторная нормировка L2.

Исходный авторский код, полный список стоп-слов и тематические словари отчёта не приложены. В платформе использован опубликованный список стоп-слов из ранее закреплённого исследовательского кода; совпадение его длины с указанной автором не подтверждает идентичности состава. Поле `authorExactCodeAvailable` равно `false`. Поэтому самостоятельные результаты маркируются `independently_recomputed`, а численные расхождения открыто опубликованы в `replicationAudit` и `text_replication_audit.csv`.

| Метрика | Авторский отчёт | Независимая реализация |
|---|---:|---:|
| Документы | 98 | 98 |
| Национальные проекты | 12 | 12 |
| Токены шести паспортов технологий здоровья | 2 571 | 2 571 |
| Токены полного корпуса | 75 539 | 75 367 |
| Признаки базового словаря | 46 519 | 45 885 |
| Признаки после стемминга | 35 509 | 35 048 |
| Признаки при использовании отдельных слов | 10 329 | 10 471 |
| Совпадения с тематическими словарями | 333 | 355 |

Восемь собственных тематических словарей находятся в `theme_dictionary.json`. Они дают 355 совпадений в 48 сочетаниях «документ — тема». Каждый контекст является дословно сохранённой содержательной единицей исходного HTML, с её XPath. Контексты не генерируются и не дописываются. Исходная авторская матрица и рисунки остаются в отчёте; самостоятельная матрица имеет отдельное происхождение.

Проверены шесть вариантов: базовый, стемминг, отдельные слова, равные веса управленческих уровней, только федеральные паспорта и только национальные паспорта. В варианте равных уровней профиль национального паспорта и средний профиль ФП отдельно нормируются, после чего получают веса по 0,5. Варианты не сводятся к изменению одной подписи графика: их значения, ранги и параметры опубликованы отдельно.

В самостоятельной реализации «Продолжительная и активная жизнь» занимает первое место по близости во всех шести вариантах. Это устойчивость результата в пределах использованных текстов и процедур. Она не доказывает общую результативность проектов или медицинскую эффективность технологий. Базовый косинус для этой пары равен примерно 0,17664. Сходство и корреляция рангов также доступны в CSV для проверки без интерфейса.

Тексты шести паспортов и контексты разделены на файлы `public/data/projects/health_technologies/documentary-text/<document_id>.json` и загружаются по потребности. Таблица `text.documentFiles` связывает идентификатор документа с файлом. Общий профиль из шести паспортов имеет `document_id: project` в таблице ведущих терминов.

## 8. Файлы и команды воспроизведения

Основные выходы:

| Путь | Назначение |
|---|---|
| `public/data/projects/health_technologies/expertise.json` | Полная редакционная раскладка отчёта, таблицы, рисунки, формулы и источники |
| `public/data/projects/health_technologies/documentary.json` | Финансовые рамки, планы, сеть, текстовая диагностика и официальные сообщения |
| `public/data/projects/health_technologies/targets.json` | Матрица целей с локаторами и картой соответствия каталогу |
| `report/coverage_manifest.json` | Контроль покрытия авторского отчёта |
| `documentary/documentary_validation.json` | Проверки и численные итоги документальной сборки |
| `documentary/documentary_sources.zip` | Исходные байты 98 паспортов |
| `documentary/documentary_inputs.json.gz` | Извлечённые профили, содержательные единицы, параметры и выбранные паспорта |
| `documentary/documentary_full.json` | Полный документальный результат для скачивания |

Последние пять коротких путей в таблице относятся к `public/downloads/projects/health_technologies/`. CSV финансов, целей, узлов, неразрешённых весов, кандидатов, терминов, тематических совпадений, косинусов и вариантов расчёта находятся рядом с `documentary_full.json`.

Команды выполняются из корня рабочей копии. Для независимого воспроизведения лучше использовать отдельную копию выпуска, поскольку сборщики записывают производные JSON и загрузки. Зависимости закреплены в общем файле требований; в нём предусмотрен `nltk==3.9.2` для варианта стемминга:

```bash
python -m pip install -r scripts/requirements-analytics.txt
python -X utf8 scripts/build_healthtech_documentary.py
python -X utf8 scripts/build_healthtech_analytics.py
python -X utf8 -m unittest discover -s tests -p "test_healthtech_documentary.py" -v
```

Документальная сборка работает без сетевых запросов и заново разбирает закреплённые байты паспортов. Проверяются SHA-256 архива и каждого документа. `parsed_healthtech_passports.json` — сохранённый промежуточный результат приёма; он не заменяет исходный HTML в обычном пересчёте.

Полная стандартная сборка платформы запускает документальный и статистический сборщики нового проекта вместе с остальными готовыми модулями:

```bash
npm run build
```

Для повторного извлечения неизменного авторского DOCX используется сохранённая карта страниц:

```bash
python -X utf8 scripts/build_healthtech_expertise.py
```

При приёме новой авторской редакции сначала необходимы рендер DOCX, визуальная проверка страниц, обновление редакционной карты и её SHA-256. Сборщик принимает `--docx /path/to/report.docx` и `--render-dir /path/to/render-directory`; каталог рендера должен содержать PDF. Для чтения PDF в этом режиме необходим PyMuPDF. При обычном воспроизведении текущего выпуска рендер не требуется: используется привязанная к исходному SHA карта `report_page_locations.json`.

`prepare_healthtech_documentary.py --release ... --fetched ...` предназначен для первоначальной подготовки корпуса из прежнего исследовательского выпуска и отдельно полученных паспортов. Он не вызывается штатной сборкой и не нужен для воспроизведения поставленного ZIP. Смена паспортной редакции требует отдельного приёма источников, проверки единиц, полноты полей, карты показателей, идентичности карточек и численных расхождений. Автоматическое обновление ЕМИСС не обновляет паспортные и правовые документы.
