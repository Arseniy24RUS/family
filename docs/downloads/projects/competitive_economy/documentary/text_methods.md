# Методика лингвистической экспертизы экономики

Основной расчёт повторяет исходную процедуру исследования 1.2.0, результаты которой включены в авторский отчёт. Корпус содержит 137 документов. Полные нормированные профили уже включены в накопительную платформу в inputs/personnel/documentary_inputs.json.gz. Их контрольная сумма и ссылка на исходный код закреплены в text_parameters.json. Восемь экономических паспортов проверяются непосредственно по сохранённым HTML: каждая строка профиля сопоставляется с адресуемой целью, задачей, показателем либо названием и характеристикой результата. При извлечении характеристики пробелы между текстовыми узлами HTML сохраняются. Суммарный знаменатель составляет 7 089 токенов.

Модель использует униграммы и биграммы, фиксированный список стоп-слов, min_df=1, max_df=0.98, max_features=20 000, sublinear_tf=True, smooth_idf=True и L2-нормировку. Биграммы могут пересекать границы соседних полей нормированного профиля, поскольку исходный препроцессор заменяет перенос строки пробелом. Такое поведение сохранено для точного повторения процедуры. Профиль проекта представляет среднее нормированных векторов его структурированных паспортов с последующей L2-нормировкой. Отдельно сохраняется исходный состав документов и жанр каждого профиля.

В сопоставимое ранжирование входят десять проектов с HTML-паспортами. Архивный профиль «Семьи» имеет другой жанр и исключён из ранжирования. «Новые технологии сбережения здоровья» отсутствует в исходном корпусе 137 документов. Корпус из 98 паспортов, использованный для более поздних дополнений платформы, не подменяет исходную модель экономического отчёта.

Русский стемминг повторяет отдельную исходную процедуру Snowball: стоп-слова исключаются перед сокращением токенов до основы, затем строится новый TF–IDF со словарём до 20 000 признаков. Дополнительные варианты платформы используют униграммы, равные веса национального и федерального уровней, только федеральные либо только национальные паспорта. При равных весах сначала берётся половина среднего вектора каждого уровня, затем нормируется их сумма. Спирменов коэффициент рассчитывается по девяти соседним проектам. Авторский отчёт не публикует этот конкретный коэффициент, поэтому он обозначен как расчёт платформы.

Семантические кандидаты выбираются среди всех 54 показателей одного национального проекта. Для каждого результата сохраняются до трёх ближайших показателей с косинусом не ниже 0,10. Получены 192 пары для 87 из 110 результатов. Принадлежность одному ФП не является условием отбора. Кандидат сохраняет адреса результата и показателя, ранг, коэффициент и статус непроверенной смысловой связи. Косинус не используется как причинный вес.

Восемнадцать словарных тем повторяют исходный dictionary.json. Совпадения внутри одной темы не перекрываются, между темами допускаются. Частота делится на число токенов соответствующего профиля и умножается на 1 000. Контексты сохраняют все найденные совпадения и адреса карточек. Совпадение, пересекающее границу полей, явно отмечается. Сумма тематических частот не равна 100% по определению.

Проверка text_replication_audit.csv сопоставляет исходные и пересчитанные межпроектные коэффициенты, результаты стемминга, частоты всех тем, каждую из 192 кандидатных пар, число признаков и токенов. Численные расхождения допускаются только в пределах 10⁻¹². Исходные иллюстрации и таблицы отчёта сохранены независимо от интерактивных представлений.
