# Передача накопительного выпуска 3.0.0-stage.1 в Codex App

Выпуск от 31 октября 2026 года продолжает `2.12.0-platform.1`. Исходное состояние репозитория `Arseniy24RUS/family` зафиксировано commit `45b6e7e055c2d9a4dc604d674273c0b20187ca36`. Комплект содержит все двенадцать проектов и их накопленные исследовательские материалы. Предыдущие архивы отдельно накладывать не требуется.

## Состав изменений

Первый этап версии 3 перерабатывает четыре страницы «Туризма и гостеприимства»: `overview`, `map`, `regions`, `causal`. Прежние адреса сохранены. Общий загрузчик получает для них отдельный пакет наблюдений. Другие туристические разделы и остальные одиннадцать проектных интерфейсов сохраняют свои возможности.

Описание реализованных задач, смысл данных и ограничения находятся в [V3_STAGE1_RU.md](V3_STAGE1_RU.md). Причинная страница содержит исследовательский протокол поддержки модульных средств размещения. Численная оценка эффекта отсутствует. Межгодовое сопоставление поездок остаётся описательным до проверки редакций методики и публикаций.

## Восстановление рабочей среды

1 ноября 2026 года рабочая среда была сброшена. Исходное основание восстановлено из указанного коммита, изменения этапа — по сохранённой истории работы. Повторная проверка восстановленного комплекта завершена со статусом `VERIFIED_WITH_LIMITATIONS`. Автоматические проверки и пройденные сценарии интерфейса подтверждены заново; приёмка скачивания и долг полной пересборки остаются открытыми. Корневой `V3_STAGE1_VERIFICATION.json` разделяет текущие результаты и историю предыдущей среды. Дата выпуска остаётся 31 октября 2026 года.

## Перенос и сборка

Распакуйте ZIP в отдельную папку. Для выпуска выбран физически полный комплект исходников и `docs/`; восстановление пропущенных копий не требуется. Сравните содержимое с текущей рабочей веткой репозитория. Сохраните историю Git, более поздние изменения пользователя, настройки публикации и расписания обновления. Commit основания обозначает проверенную исходную версию этого этапа. Изменения, появившиеся в репозитории после него, требуют отдельной проверки при объединении.

Работу выполняйте в отдельной ветке. В новой среде установите зависимости из `scripts/requirements-analytics.txt`. Подготовленные PDF входят в комплект, поэтому обычная сборка не требует LibreOffice. Контрольные суммы авторских DOCX в `inputs/revised_expertises/edition-2026-10-30` должны сохраняться.

```bash
python -m pip install -r scripts/requirements-analytics.txt
npm test
python -m unittest discover -s tests -p 'test_*.py' -v
npm run build
npm run validate
python scripts/build_pages.py --report PAGES_BUILD_VERIFICATION.json
```

Сборка использует включённые данные. Обращение к ЕМИСС выполняется отдельными процедурами обновления. Дата выпуска интерфейса не заменяет даты наблюдений и их получения.

Полная сборка предыдущей среды завершилась успешно, но не воспроизвела все сохранённые результаты побайтово. Долг воспроизводимости касается CRLF/LF, служебных полей gzip, округления PCA, порядка равных значений и редакторских полей инфраструктурного `methods.json`. Перед выпуском требуется просмотреть изменения остальных исследований. Ранее базовые выходы были восстановлены для `public/` и `docs/` по отдельности, после чего синхронизированы только 43 копии v3 и отдельно пересчитаны оба индекса скачивания. Общая команда сборки сама по себе не воспроизводит эту контролируемую процедуру. После восстановления полный offline-build не повторялся. Побайтовая сверка подтверждает сохранность 6 842 файлов данных и материалов и 5 478 проектных файлов остальных одиннадцати исследований. Оба индекса проверены отдельно по собственным деревьям: по 1 959 корректных записей. Устаревшая запись public-индекса для `demography/upstream/manifest.json` исправлена и перепроверена. Долг воспроизводимости остаётся `OPEN`; подробности указаны в `V3_STAGE1_VERIFICATION.json`.

Для обычной локальной проверки запустите `npm run dev`. Launcher выбирает `python` в Windows и `python3` в остальных системах. Переменная `PYTHON` позволяет указать другой исполняемый файл. По умолчанию сервер доступен только по адресу `127.0.0.1:8080`. Параметры `--host`, `--port` и `--strictPort` поддерживают управляемый инструмент просмотра.

В управляемой среде применяйте её штатный инструмент браузерной проверки. CI и обычная локальная среда используют следующую последовательность:

```bash
python -m pip install -r scripts/requirements-browser.txt
python -m playwright install chromium
python tests/run_browser.py --directory .pages --output ../qa-v3-stage1
```

## Проверка исследовательского действия

Откройте обзор туризма и выберите период. Перейдите к карте, ранжировке и таблице, затем добавьте несколько территорий и сравните их траектории. Проверьте сохранение выбора, удаление последней территории, объяснение недоступного периода и региона, переход в причинный протокол и обратно. Откройте исходную ячейку, сохраните JSON исследования и проверьте его арифметику:

```bash
python scripts/reproduce_tourism_research.py tourism-research-2025-12-31.json --output tourism-research-check.json
```

Имя входного файла замените на фактическое. Процедура использует стандартную библиотеку Python и включённые в JSON наблюдения. Статус `PASS` означает совпадение повторного расчёта с сохранённым результатом. Проверка не подтверждает редакцию первичного статистического источника и не устанавливает причинную связь.

В восстановленной среде повторно пройдены 31 из 31 тестового файла Node, 569 тестов Python за 90,398 секунды и `npm run validate`. Публикационная сборка прошла шесть из шести проверок. Открыты четыре туристических маршрута; обзор и причинный протокол проверены визуально. Срез сентября 2026 года сохраняет точный период и фокус. Выбор территорий 77, 23 и 24 связан между картой, таблицей и профилем; таблица показывает по 15 строк на страницу. Недоступный период 31.01.2027 и регион 99 получают объяснения без подстановки другого среза или профиля; старая редакция вызывает предупреждение. Обзоры «Семьи», «Продолжительной и активной жизни» и «Кадров» открыты с актуальными PDF от 30.10.2026 без наблюдаемых ошибок приложения.

Мобильная проверка обзора и причинного протокола выполнена в контейнере шириной 390 пикселей. Внутренний viewport составлял 375 пикселей из-за полосы прокрутки; ширина прокрутки документа и body также равнялась 375 пикселям. Горизонтального переполнения не обнаружено. Свежий файл скриншота в общей рабочей папке не сохранён; исторический снимок не обозначается новой проверкой.

Скачивание после восстановления требует повторной ручной приёмки. JSON-событие вернуло путь, но файл не найден в файловой системе браузера и общей рабочей папке. API скачивания PNG завершился ошибкой; SVG повторно не проверялся. Причина не установлена. До сброса среды JSON действительно прошёл повторный расчёт по 1 806 наблюдениям, 21 периоду и 84 точкам траекторий, а PNG 1560 × 968 пикселей был скачан и визуально проверен. Эти результаты остаются историей, а не подтверждением свежего скачивания.

Перед закрытием этого ограничения вручную сохраните JSON и выполните указанную процедуру Python, затем скачайте SVG и PNG и проверьте читаемость подписей и значений. При дальнейших изменениях проверяйте актуальные документы, каталог `research/reports.html`, карты, калькуляторы и возврат браузером назад. Итоги браузерной проверки относятся к фактически пройденным сценариям, размерам экрана и версии сборки.

## Публикация и накопительный комплект

Полный `docs/` предназначен для локального просмотра. Команда `npm run build:pages` формирует отдельную `.pages/`, проверяет размер публикации и точное восстановление JSON из gzip. Действующие публикационные workflow используют `.pages/`. Полные `public/` и `docs/` сохраняют исходные данные. Временные материалы проверки размещаются вне репозитория.

Упаковка выполняется после завершения правок и проверок, без параллельного изменения файлов. Выходной каталог должен находиться вне checkout:

```bash
python scripts/package_platform.py --output ../deliverables-v3-stage1 --compression-level 9 --date 2026-10-31
```

Упаковщик создаёт физически полный накопительный ZIP, перечень скачиваемых файлов и контрольные суммы. Все файлы `docs/` входят непосредственно в архив. `RELEASE_MANIFEST.json` фиксирует состав и SHA-256; проверяются CRC архива и контрольная сумма каждого файла. Старые манифесты нельзя использовать для проверки изменённого выпуска. `PACKAGE_COPIES.json` в рабочем репозитории содержит версию `3.0.0-stage.1` и пустой список `copies`, а в полный ZIP не включается.

Параметр `--deduplicate-docs` остаётся опциональным для других вариантов распространения. Он исключает только подтверждённые побайтовые копии `docs/`, создаёт отдельный манифест и требует восстановления при первом запуске. В данном выпуске этот режим не используется.

Корневой `PAGES_BUILD_VERIFICATION.json` обновляется после последней сборки. Он расположен вне входного `docs/` и выходного `.pages/`, поэтому не входит в собственную проверку. `RELEASE_MANIFEST.json` не хеширует себя. `DOWNLOAD_MANIFEST.json` и `SHA256SUMS.txt` создаются рядом с готовым ZIP, вне репозитория. После упаковки исходные файлы должны оставаться неизменными; последующая правка требует нового архива.

Сама упаковка не отправляет коммиты и не публикует сайт. Feature-ветка и draft PR запускают проверку CI; действующий deploy workflow требует push в `main` или `master`, совпадающую с основной веткой репозитория, либо ручного запуска на этой ветке. Объединение PR и публикация выполняются отдельно после просмотра результата.
