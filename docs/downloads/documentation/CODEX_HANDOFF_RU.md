# Передача накопительного выпуска 3.0.0-stage.2 в Codex App

Выпуск от 1 ноября 2026 года продолжает `3.0.0-stage.1`, commit `2789bfb5340c3a9a937a40527b444efd18f65a81`. Исходное основание версии 3 – `2.12.0-platform.1`, commit `45b6e7e055c2d9a4dc604d674273c0b20187ca36` репозитория `Arseniy24RUS/family`. Полный ZIP включает все двенадцать проектов и готовый `docs/`; наложение предыдущих архивов не требуется.

## Содержание второго этапа

Общий выбор территории и периода действует на основной карте и региональном распределении «Семьи», «Продолжительной и активной жизни», «Кадров» и «Туризма». Ссылка хранит границы окна, смысл наблюдения и опубликованную частоту. Недоступный срез не получает ближайшее наблюдение. Дополнительные и многопериодные анализы сохраняют собственные даты и явно указанную область применения. Подробное описание находится в [V3_STAGE2_RU.md](V3_STAGE2_RU.md).

Сохранены четыре туристические страницы первого этапа, исходные наблюдения и протокол оценки воздействия. Численный причинный эффект отсутствует. Дата интерфейсного выпуска не изменяет даты наблюдений или получения статистики. Полные авторские экспертизы от 30.10.2026 остаются самостоятельной редакцией документов.

Браузерная приёмка дополнена скачиванием JSON, CSV, SVG и PNG, независимым повторным расчётом JSON и сценариями перехода между четырьмя проектами. Итоговые записи проверки находятся в корневом `V3_STAGE2_VERIFICATION.json`. Исторические записи первого этапа сохранены под прежними именами.

## Работа с исходниками

Распакуйте ZIP в отдельную папку и сопоставьте его с текущей feature-веткой. Сохраните историю Git, более поздние изменения пользователя, настройки публикации и расписания обновления. Выпуск подготовлен в `codex/v3-01-tourism`, draft PR № 2. Объединение с основной веткой и публикация сайта являются отдельными действиями.

Для обычного просмотра достаточно Python 3.11 или новее. Запустите `start_local.bat`, `bash start_local.sh` или `python scripts/preview_platform.py`. С Node.js доступна команда `npm run dev`; переменная `PYTHON` позволяет выбрать интерпретатор. Адрес по умолчанию – `http://127.0.0.1:8080/`. HTML-файл следует открывать через HTTP-сервер.

Для проверки расчётного кода установите зависимости и выполните тесты:

```bash
python -m pip install -r scripts/requirements-analytics.txt
npm test
python -m unittest discover -s tests -p 'test_*.py' -v
npm run validate
```

Если изменены интерфейс, расчётные процедуры или редакционная документация, но аналитические выходы сохраняются в прежней редакции, примените контролируемую синхронизацию:

```bash
npm run sync:release -- --dry-run
npm run sync:release
npm run validate
```

Команда обновляет `docs/src/`, код и документацию в обоих каталогах скачивания. Индексы рассчитываются отдельно по собственным файлам `public/` и `docs/`. Деревья исследовательских данных не копируются друг поверх друга. Некоторые сохранённые аналитические файлы этих деревьев законно различаются; массовое копирование требует отдельного обоснования.

## Полная сборка

`npm run build` заново рассчитывает включённые аналитические материалы и формирует `docs/`. Выполняйте его в отдельном checkout, затем просмотрите отличия перед включением новых выходов в релиз. Обращение к ЕМИСС выполняется отдельными процедурами обновления. Подготовленные PDF входят в комплект; обычная сборка не требует LibreOffice.

Редакторские поля инфраструктурных методов теперь читаются из `scripts/infrastructure_method_review.json` обоими сборщиками. Изменять эти поля следует в данном источнике. Проверка останавливает сборку при неполном, повторном или лишнем составе методов.

Окончания строк и метаданные создаваемых сборкой gzip/ZIP закреплены; порядок равных TF–IDF весов определён явно. Совпадение двух запусков внутри одной среды не заменяет проверку результатов между разными версиями библиотек и процессорами. Фактические выводы полной сборки записаны отдельно в проверке второго этапа. Первичные вложения и авторские документы нельзя перекодировать ради совпадения хэшей выходных файлов.

## Браузер и публикационная копия

В управляемой среде используйте штатный инструмент просмотра и браузерной проверки. CI и обычная локальная среда запускают существующий набор Chromium:

```bash
python scripts/build_pages.py --report PAGES_BUILD_VERIFICATION.json
python -m pip install -r scripts/requirements-browser.txt
python -m playwright install chromium
python tests/run_browser.py --directory .pages --output ../qa-v3-stage2
```

Компактная `.pages/` проверяется по предельному размеру, сохранности исходных файлов и точному восстановлению gzip. Корневой отчёт находится вне входного и выходного деревьев. Полный `docs/` остаётся в накопительном архиве.

В интерфейсе выберите территорию и период на карте туризма, перейдите в другой поддерживаемый проект и проверьте область применения. Если точного окна нет, должен оставаться доступным явный выбор существующего периода. Возврат браузером и обновление страницы должны сохранить запрос. Для «Семьи» сравните карту с многопериодной PCA, для «Здоровья» – основную карту с дополнительными анализами.

Скачанный JSON туризма проверяется командой:

```bash
python scripts/reproduce_tourism_research.py tourism-research-2026-09-30.json --output tourism-research-check.json
```

Укажите фактический путь файла. Проверка повторяет арифметику по включённым строкам и не удостоверяет применённую редакцию первичной статистической методики. CSV всего среза должен включать 85 регионов, даже если поиск оставляет одну строку в интерфейсе. SVG и PNG должны сохранять читаемые заголовок, период, единицу и источник.

## Накопительный архив

После завершения правок, синхронизации и проверок остановите изменения исходников и запустите упаковку с выходным каталогом вне checkout:

```bash
python scripts/package_platform.py --output ../deliverables-v3-stage2 --compression-level 9 --date 2026-11-01
```

Режим `--deduplicate-docs` в данном выпуске не применяется. Все копии `docs/` входят физически. `PACKAGE_COPIES.json` имеет версию `3.0.0-stage.2` и пустой список `copies`; упаковщик не включает его в полный архив.

`RELEASE_MANIFEST.json` фиксирует состав и SHA-256 каждого файла, кроме самого манифеста. `DOWNLOAD_MANIFEST.json` и `SHA256SUMS.txt` создаются рядом с ZIP. После упаковки проверяются CRC всех записей, SHA-256 каждого файла манифеста и точное совпадение вложенного манифеста с корневым. `V3_STAGE2_PACKAGE_VERIFICATION.json` создаётся после этой проверки и хранится вне самого ZIP, чтобы исключить цикл контрольных сумм.

Исходный code commit и последующий commit с квитанцией упаковки различаются по назначению. После создания архива исходные файлы должны оставаться неизменными. Любая последующая содержательная правка требует нового архива и новых квитанций.

## Продолжение версии 3

Перед публикацией через workflow полной сборки необходимо сверить исторические редакции прогнозных выходов и зафиксировать принимаемый набор аналитических результатов. Накопительный ZIP сохраняет прежние данные; успешность пересчёта сама по себе не разрешает заменить их новым результатом. Следующий интерфейсный этап – общая главная исследовательской платформы и последовательное распространение согласованных компонентов на остальные проекты. Сначала следует определить их фактические временные и территориальные контракты. Совпадение параметров URL не даёт основания объявлять разные показатели сопоставимыми. Полная приёмка WCAG 2.2 AA, полевые показатели производительности и внешняя научная оценка остаются отдельными задачами программы качества.
