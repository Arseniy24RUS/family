# Перенос раздела туризма в Codex App

Накопительный комплект продолжает `2.8.0-dataeconomy.1` и содержит ранее подготовленные разделы. Его следует сопоставлять с текущей веткой `Arseniy24RUS/family`, сохраняя историю Git и последующие изменения пользователя. Исходный сайт, от которого продолжен комплект, имеет коммит `50ad21c1ad1c94e3cf07857363333df120558617`.

## Задача

Перенести содержимое накопительного комплекта в рабочую копию `Arseniy24RUS/family`, проверить новый раздел «Туризм и гостеприимство» и сохранить существующие разделы. Если ZIP использует `PACKAGE_COPIES.json`, выполнить `python scripts/restore_package_copies.py --verify` в распакованной папке перед сравнением и переносом. Проверить изменения по `RELEASE_MANIFEST.json` и не накладывать поверх него старые накопительные архивы.

Открыть `#/projects/tourism/overview` и все 21 маршрута раздела. Проверить фильтры источника, территории, периода и категории, исходные значения, причины исключения, карты, финансовые основания, документальные связи, полные тексты, условные расчёты и скачивание файлов. Проверить текстовые страницы `research/projects/tourism/`, включая ссылки на иллюстрации и исходный DOCX.

Проверить, что `62902` используется для экспорта в долларах США, а `63347` – для иностранных размещений в миллионах человек. Исходный каталожный счётчик пяти показателей должен быть отделён от шести содержательно обеспеченных показателей после проверки привязки. Число источников, число карточек и число наблюдений имеют самостоятельный смысл.

Проверить сохранность спорных исходных нулей и их исключение из аналитики. Промежуточная публикация не должна становиться годовым фактом. Арифметическая сумма паспортных строк не должна подписываться консолидированным ресурсом. Условная траектория не должна обозначаться статистически подтверждённым прогнозом. PCA, кластеризация и причинные эффекты не должны появляться без новых допустимых данных и расчётов.

Проверить переключение между туризмом и ранее завершёнными исследованиями. Смысловая страница должна сохраняться, когда доступна в обоих проектах, а проектные фильтры не должны переноситься в чужой раздел. Проверить старые маршруты «Семьи», включая `#/authors`, её палитру и отсутствие раздела «Об авторах» у остальных проектов.

Проверить верхнюю навигацию и таблицы на узком экране, локальные шрифты и официальный цвет туризма `#208076`. Все проверки браузера выполнять через HTTP с проектным префиксом `/family/`, соответствующим GitHub Pages.

## Команды

```bash
python scripts/restore_package_copies.py --verify
python -m pip install -r scripts/requirements-analytics.txt
npm test
npm run build
npm run validate
npm run build:pages
python -m unittest discover -s tests -p "test_*.py"
```

Для проверки компактной публикации выполните `python tests/run_browser.py --directory .pages --suite browser_tourism --output <каталог_вне_репозитория>`. Полная браузерная проверка этого выпуска в текущей среде не завершена. Полный `docs/` предназначен для локального просмотра; GitHub Pages получает `.pages/`, которая формируется отдельным шагом и проходит проверку размера и точного восстановления JSON. Подробности в `PAGES_PUBLICATION_RU.md`. Настройки существующего workflow ЕМИСС, секреты доступа и параметры GitHub Pages необходимо сохранить. Секреты не входят в ZIP и не добавляются в публичные файлы.

После переноса сверить исходный отчёт с SHA-256 `bc1950af5a03bdfa2609317a581f06af4fe5ef3f714176e3f8947e926401aac5`. Сведения о составе и ограничениях приведены в `TOURISM_RELEASE_RU.md`.
