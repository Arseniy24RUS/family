# Размер и полнота накопительного ZIP

Начиная с `2.6.0-environment.1` одинаковое содержимое исходных папок и каталога готового сайта `docs/` упаковывается в ZIP один раз. Ранее одинаковые байты присутствовали в обоих местах. ZIP с меньшим размером может содержать больше исследовательских материалов благодаря изменению способа упаковки.

| Выпуск | Размер ZIP, байт | Файлов непосредственно в ZIP | Файлов в полном комплекте после восстановления |
|---|---:|---:|---:|
| `2.5.0-infrastructure.1` | 498 845 901 | 4 442 | 4 442 |
| `2.6.0-environment.1` | 274 085 545 | 2 634 | 4 913 |

Для второго выпуска 2 279 готовых копий сайта восстанавливаются из побайтово одинаковых файлов, физически включённых в архив. После восстановления сверяются полный состав и SHA-256. Предыдущие архивы для восстановления не требуются.

## Как устроена проверка

`RELEASE_MANIFEST.json` описывает полный логический состав, базовый выпуск и контрольную сумму каждого файла. `PACKAGE_COPIES.json` указывает, из какого включённого файла создаётся каждая пропущенная копия `docs/`. Только подтверждённое совпадение размера и SHA-256 допускает такую упаковку. Исследовательские документы и уникальные файлы не исключаются.

При первом запуске `start_local.bat`, `start_local.sh` или `scripts/preview_platform.py` отсутствующие копии восстанавливаются автоматически. Процедура использует стандартную библиотеку Python, сеть и аналитические зависимости не требуются. Существующие файлы не перезаписываются. Проверка `python scripts/restore_package_copies.py --verify` дополнительно сверяет уже имеющиеся копии.

Перед переносом через Codex App следует выполнить восстановление с `--verify` либо полную сборку. После этого `docs/` содержит обычный готовый сайт для GitHub Pages. Сохранение предыдущих ZIP остаётся удобным способом иметь отдельные версии, накладывать их на текущий комплект не нужно.

## Проверка версии 2.7

До изменений сверены все 4 912 записи манифеста выпуска 2.6, исключая сам манифест. Все контрольные суммы совпали. Финальная проверка сравнивает старые пути и адреса скачивания с новым комплектом. Общие файлы маршрутизации, сборки, документации и каталога загрузок изменяются для добавления проекта. Прежние исследовательские материалы проверяются отдельно от этих ожидаемых изменений.

Результат сравнения включён в `COMPETITIVE_VALIDATION.json`. Перед выдачей единый ZIP проходит проверку CRC, контрольных сумм логических файлов, чистую распаковку, автоматическое восстановление, запуск HTTP и проверку страниц.

## Проверка версии 2.8

Базовый комплект `2.7.0-competitive.1` имеет размер 285 892 245 байт, содержит 2 981 физический файл и 5 564 логических файла после восстановления. До начала новой работы сверены все 5 563 записи его манифеста, исключая сам манифест. Пропусков и расхождений SHA-256 не обнаружено.

Выпуск `2.8.0-dataeconomy.1` включает «Экономику данных» вместе со всеми предыдущими материалами. Сравнение с базовым ZIP проверяет каждый прежний путь, адрес скачивания и изменённый общий файл. Итоговый размер и физический состав нового ZIP записываются упаковщиком в отдельный `DOWNLOAD_MANIFEST.json`. Полный состав находится в `RELEASE_MANIFEST.json`, правила восстановления – в `PACKAGE_COPIES.json`. Предыдущие ZIP для запуска нового комплекта не требуются.
