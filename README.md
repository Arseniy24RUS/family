## Публикация / установка поверх 1.0–1.1

При обновлении уже работающего репозитория сохраните его каталоги `public/data/latest`, `inputs/upstream` и `inputs/cohort`: они могут содержать более свежие данные или собственные базы. После переноса кода верните их до запуска сборки. Для новой установки ничего сохранять не требуется.

Распакуйте весь архив и перенесите содержимое папки `Semya_Research_Platform` в корень репозитория с заменой файлов, включая скрытую `.github`. Не переносите только каталог `docs`, если требуется автоматический пересчет. В Settings → Pages выберите **GitHub Actions**. Запустите **Deploy research platform**, затем проверьте summary его шага источников и страницу передвижки.

Ежемесячный сценарий **Refresh EMISS and deploy** выполняется 8-го числа в 06:23 UTC и может запускаться вручную. Внешние ошибки оставляют последнее корректное состояние. Для выполнения commit workflow нужны разрешения contents: write, уже указанные в YAML. Оба сценария сохраняют проверенные входы и результаты в репозитории для следующего запуска. При ограничениях защищённой ветки push может быть запрещён; в таком случае workflow завершится с явной ошибкой, а не молча потеряет кеш. В organization эти разрешения могут быть ограничены администратором.

Готовая сборка находится в `docs/` и доступна без npm-пакетов. Публикация из ветки `/docs` работает для готового среза, но для автоматических обновлений выбирайте Actions.

Распакуйте ZIP. Загрузите **содержимое** папки `Semya_Research_Platform` в корень нового репозитория, включая скрытую папку `.github`. Для большого количества файлов удобнее GitHub Desktop или Git. Сохраняйте структуру каталогов; не загружайте только сам ZIP.

Для первого обращения к ЕМИСС отдельно запустите **Refresh EMISS and deploy → Run workflow**. Поле `source` можно оставить пустым для всех 16 источников или задать `data_21` для проверки одного ряда. После проверки откройте страницу сайта **«Обновление ЕМИСС»**. Успешная публикация сайта сама по себе не означает успешную загрузку статистики.

## Три независимых слоя

**Архив экспертизы** — неизменяемые исходные значения и результаты исследовательского среза. Текстовые и финансовые разделы, исходная кластеризация, сети и прогнозы остаются привязаны к этому слою.

**Проверенный слой ЕМИСС** — статистика после серверной загрузки, проверки и объединения с сохранённой историей. Переключение доступно в атласе, исследователе данных и вычислительной лаборатории. До первой успешной загрузки явно показывается архивный набор. При последующей ошибке сохраняется последний корректный набор, а его состояние обозначается как не подтверждённое текущей попыткой.

**Новый расчёт пользователя** — результат лаборатории с собственными параметрами. Пересчёт не изменяет файлы исходной экспертизы. Совпадение названия метода не означает, что настройки нового расчёта совпадают с настройками первоначального исследования.

## ЕМИСС: реализовано и проверено отдельно

В адаптер перенесена схема из приложенного CDO-проекта: чтение HTML-метаданных и фильтров → POST-запрос выгрузки `sdmx` → разбор ответа → нормализация → проверки → публикация. Браузер получает готовые локальные JSON, поэтому ему не нужен прямой доступ к ЕМИСС и не мешает ограничение CORS внешнего сайта.

Проверка запланирована на **8-е число каждого месяца, 06:23 UTC**. Дата выбрана для платформы и не является установленной датой публикации ЕМИСС. В исходном массиве есть годовые, месячные и накопительные ряды; запуск раз в месяц не меняет их периодичность.

В конфигурации заранее задан идентификатор `62852` для источника `data_21`. Для остальных источников реализован поиск точного наименования в действующем каталоге ЕМИСС. Неоднозначность идентификатора, дополнительного измерения или периода останавливает обновление соответствующего источника. Программа не выбирает первую попавшуюся категорию. Для восьми отсутствующих индикаторов предусмотрен отдельный поиск кандидатов без автоматического включения неподтверждённого ряда.

**Живой обмен с ЕМИСС в среде подготовки не подтверждён:** проверочный GET завершился ошибкой DNS. В архиве нет новых значений, полученных таким запросом. ## Локальный запуск

Готовая сборка находится в `docs/`. Достаточно Python 3:

```bash
python -m http.server 8080 --directory docs
```

Откройте `http://localhost:8080/`. В Windows можно запустить `start_local.bat`. Двойной щелчок по `index.html` с адресом `file://` не поддерживается: модулям и загрузке JSON нужен HTTP.

Для изменения интерфейса нужен Node.js 22 или новее. У проекта нет npm-зависимостей, поэтому установка пакетов не требуется:

```bash
npm test
npm run build
npm run validate
```

После изменения `src/` пересоберите `docs/` и обновите страницу браузера. `public/` — данные и загрузки; `src/` — исходный интерфейс; `docs/` — итог сайта. Не редактируйте только `docs/`: очередная сборка заменит его.

При изменении исходных статистических CSV или GeoJSON:

```bash
python -m pip install -r scripts/requirements-research.txt
python scripts/build_data.py
npm run build
npm run validate
```

Новый исходный массив лучше выпускать отдельной версией, сохраняя первоначальный срез. Обычное обновление ЕМИСС не вызывает `build_data.py` и не переписывает архив исследования.

Браузерные проверки включают 32 маршрута/вкладки на десктопе и 32 на мобильном экране, реальные экспортные операции, переключение карт и узлов, а также совпадение трёх расчётов JavaScript и Python. Ограничение браузерного прогона: использован Chromium с подачей файлов через Playwright routing, поскольку переход на обычный URL блокировался политикой среды. Исполнялись неизменённые модули приложения, реальные Web Worker и расчёты, но не проверялся фактически размещённый сайт. Подробности: [VALIDATION.md](documentation/VALIDATION.md).

## Исследовательские ограничения

Расхождения исходных таблиц не исправлены незаметно. В интерфейсе отдельно объяснены различия годового и оперативного слоя, отсутствие данных, значения долей за пределами обычного диапазона, различия файлов выбора числа кластеров и итоговой классификации. Прогнозные линии показывают сохранённые вычисления, а не доказанный причинный эффект. Полного первоначального кода обучения всех прогнозных моделей в переданном комплекте нет; он не заменён новым кодом под прежним названием.

Новые загрузки не обновляют автоматически экспертные выводы, нормативную редакцию паспорта или бюджет. Их актуализация требует отдельного исследовательского решения. Сайт не является официальной системой мониторинга Правительства или Росстата.

Географические границы воспроизводят предоставленный пользователем `ru_regions.geojson`; числовой охват и геометрический слой описаны раздельно. Картографическое отображение не устанавливает международно-правовой статус территорий.
