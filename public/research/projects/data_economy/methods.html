3.10 Приоритеты повышения проверяемости

Первое необходимое изменение — публикация версионного паспорта каждого ряда: формула, совокупность, знаменатель, период накопления, дата исходных данных, разрешённый перенос прошлых значений и применённая редакция методики. Для переходов между редакциями следует давать параллельный расчёт хотя бы одного общего периода. Особо актуальны октябрьская поправка № 931, новая конструкция цифровой зрелости и изменение методики качества статистических показателей. Наличие поправки не устанавливает само по себе, с какого наблюдения она фактически применена: эту дату обязан раскрывать поставщик ряда. с. 38 исходного отчёта

Второе изменение — типизированные проверки данных. Доли с естественной границей 100%, индексы к базовому году, накопленные количества и моментные состояния требуют разных правил. Для Ц.11 верхняя граница 100% недопустима. Числовой ноль, отсутствие публикации, технический заполнитель и повтор прошлого значения должны иметь разные статусы. Исправление фильтра необходимо сопровождать повторной проверкой всех производных таблиц и графиков, поскольку ошибочно отброшенное наблюдение меняет дату последнего доступного результата. с. 38 исходного отчёта

Практически такая проверка должна формировать протокол исключений, содержащий исходное значение, применённое правило и основание решения. Нельзя незаметно заменять подозрительное значение пропуском, предыдущим числом или самостоятельно рассчитанным аналогом. Для спорных наблюдений целесообразно сохранять две доступные версии: опубликованную и аналитически очищенную, с перечнем различий. Поставщику данных необходимо направлять запрос на пояснение конкретной компоненты или периода. Исправление должно становиться новой версией ряда с датой и причиной, чтобы пользователь мог воспроизвести вывод, сделанный до пересмотра. с. 38 исходного отчёта

Третье изменение — разделение планового достижения, работы механизма и общественного результата. План показывает нормативное обязательство; факт — наблюдение по конкретной методике; механизм — связь мероприятия с промежуточным изменением; причинный эффект требует самостоятельного дизайна оценки. Для доступности Интернета общественный результат раскрывают качество и использование, для электронных услуг — завершённое обслуживание и нагрузка заявителя, для ПО — устойчивость процессов, для ИИ — подтверждённый результат внедрения. Такой подход сохраняет управленческую роль официальных индикаторов и одновременно делает выводы о результативности проекта проверяемыми. с. 38 исходного отчёта
