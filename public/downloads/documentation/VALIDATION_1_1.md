## Как выполнялась браузерная проверка

Использован Chromium через Playwright. Browser plugin в данной среде отсутствует. Переход Chromium на локальный HTTP-адрес блокируется политикой среды (`ERR_BLOCKED_BY_ADMINISTRATOR`). Поэтому тесты предоставляли фактические файлы из `docs/` через перехват запросов Playwright на виртуальном домене `semya.test`. Код приложения, вычисления, SVG, обработчики событий, Web Workers, создание PNG и скачивание файлов исполнялись в браузере. Такой прогон проверяет приложение, но не работу внешнего хостинга, DNS, CORS источников или GitHub Actions.

Официальные фотографии в отдельном тесте намеренно делались недоступными: проверен показ инициалов вместо повреждённого изображения. Успешная загрузка всех трёх предоставленных институциональных логотипов проверена по фактической ширине загруженного изображения.

Визуально проверены основная сине-зелёно-жёлтая шкала, тёмно-синяя навигация, точное название, порядок логотипов на светлом фоне, авторские карточки, читаемость элементов управления, легенды, отсутствие горизонтального переполнения страницы и масштаб возрастной пирамиды на узком экране. При подготовке устранены проблема запуска нового рабочего потока, наложение дат на временной оси и чрезмерное уменьшение подписей графика при мобильном масштабе.

## Состояние включённых данных

В пакет входят 172 рассчитанных месячных ряда: СКР и СКР третьих и последующих детей для России и 85 регионов с исходными наблюдениями. История каждого ряда в данном срезе охватывает январь 2025 — март 2026 года; продолжение — апрель 2026 — декабрь 2030 года. Годовые строки не подмешаны в месячную обучающую последовательность. Четыре территории справочника без наблюдений по каждому из этих показателей остаются без прогноза. СКР3+ не превышает СКР в парных сохранённых траекториях; эта проверка не заменяет проверки содержательной сопоставимости показателей.

Файл `monthly_indicators.csv` содержит 12 384 строки наблюдений и прогнозов; `model_weights_validation.csv` — 516 строк с характеристиками трёх моделей для каждого рассчитанного ряда. Новая модель `monthly-log-ensemble/1.1.1` не выдаётся за первоначальный ансамбль экспертизы. Условные полосы не калиброваны на длинном горизонте и не описывают все структурные изменения.

**Реальные половозрастные входы в данной среде не получены: в манифесте передвижки 0 готовых территорий.** Наблюдаемая возрастная база не заменялась данными ранее выполненного прогноза, синтетической структурой или приблизительным распределением. Программное ядро, пакетный пересчёт, интерфейс, импорт и экспорт реализованы и проверены; реальная национальная и региональные траектории численности должны быть рассчитаны после успешной загрузки настоящих входов. Автоматический загрузчик включён в первую публикацию и последующие обновления. Он проверяет листы `by_age` и `status`, общий наблюдаемый базовый год двух полов и полный возрастной ряд; при несовпадении контракта отказывается от расчёта и показывает причину.

Сквозной тест «XLSX → исходная возрастная структура → обе месячные проекции → публикация → сохранение старого расчёта при ошибке» выполнен на временных синтетических файлах. Они не включены в реальный слой платформы. Учебная территория доступна отдельно, открывается только по выбору пользователя и явно подписана как искусственный пример.

## Внешние операции, которые не подтверждены

Не проверены размещённый сайт GitHub Pages, реальный запуск workflow, успешное получение SDMX ЕМИСС, скачивание пяти больших XLSX/CSV из авторского репозитория и фактические пиксели портретов. Запрос внешней возрастной базы при подготовке завершился ошибкой разрешения имени; повторная попытка получить бинарный файл через доступный GitHub-коннектор также не дала байтов файла. Ссылки на официальные портреты сохранены; при успешном получении workflow сохраняет локальные копии, а при недоступности остаются инициалы.

## Проверка после размещения

В настройках Pages используется источник GitHub Actions. Workflow `Deploy research platform` собирает интерфейс, пересчитывает коэффициенты, запрашивает возрастные входы, пытается сохранить портреты, проверяет результат и сохраняет успешно полученные входы и расчёты в репозитории. Workflow `Refresh EMISS and deploy` дополнительно запрашивает свежие наблюдения ЕМИСС. Ежемесячное расписание платформы — 8-е число, 04:23 UTC; оно не обозначает установленный день публикации ЕМИСС.

После первого внешнего запуска проверяются сводка Actions, страница «Обновление ЕМИСС» и манифест передвижки. Наличие новой даты запуска не означает, что возрастная база, ОПЖ или миграция стали новыми наблюдениями. Для каждого входа остаются видимыми происхождение, период и статус.

При обновлении уже действующего репозитория сохраните `public/data/latest/`, `inputs/upstream/` и собственные `inputs/cohort/`: пакет не должен откатить накопленную статистику. Если защита ветки запрещает запись рабочего процесса, необходимо разрешить соответствующую запись либо адаптировать публикацию данных к принятому в репозитории процессу согласования.
