# Адаптер ЕМИСС и диагностируемое обновление

## Основание реализации

Механизм адаптирован из переданного проекта `CDO_dashboard_external_audit_2026-06-26`. Использована его схема обращения к ЕМИСС: HTTP-сессия с cookies, получение страницы показателя, извлечение структуры фильтров, POST на endpoint выгрузки с `format=sdmx`, затем разбор XML. Полный backend CDO, база PostgreSQL, VPN-контейнеры и пользовательский API-сервер для статической платформы не требуются.

ЕМИСС предоставляет данные через интерфейс, структура которого может изменяться. Данный адаптер не является официальной гарантированной спецификацией Росстата. Прямой запрос в среде подготовки завершился ошибкой DNS, поэтому работоспособность именно с текущим живым ответом не утверждается.

## Настройки

Главный файл — `scripts/emiss_sources.json`. Источники привязаны к первоначальным `data_20`…`data_35`. Для каждого заданы код проекта, точные названия, единица, начальный год, допустимые типы периодов и минимальный региональный охват. У `data_21` предварительно указан идентификатор `62852`; остальные идентификаторы разрешаются по каталогу.

При совпадении названия у нескольких действующих показателей автоматический выбор прекращается. Найденный идентификатор после успешного чтения сохраняется в manifest и используется при следующем запуске. Название всё равно перепроверяется. Исключённая запись каталога не получает приоритета над действующей.

`field_overrides` позволяет явно сопоставить поля метаданных ролям `territory`, `year`, `month`. `dimension_defaults` задаёт подтверждённые значения дополнительных измерений. Идентификаторы полей и категорий необходимо брать из полученных метаданных, не придумывать. Например, при наличии пола, типа местности или категории получателя нельзя молча выбирать первый элемент. Изменение смыслового измерения уже опубликованного ряда блокируется.

Числовой лимит `max_cells` ограничивает ожидаемый размер запроса. Если он превышен, источник требует уточнения диапазона или фильтров. В текущей реализации не предусмотрено незаметное усечение числа регионов/лет для обхода лимита.

## Последовательность запроса

`emiss_adapter/catalog.py` читает каталог. `metadata.py` разбирает встроенные данные фильтров как JSON5, не исполняя JavaScript. `client.py` формирует запрос, включая повторяющийся параметр `selectedFilterIds`, `lineObjectIds`, `columnObjectIds` и `filterObjectIds`. Простое превращение списка параметров в словарь уничтожило бы повторяющиеся значения; тест проверяет сохранение списка.

`sdmx.py` читает XML без загрузки внешних сущностей. `normalize.py` восстанавливает территорию, год, месяц/накопительный период и подтверждённые дополнительные измерения. Если месяцы не обозначены в общем ответе, адаптер может запросить каждый явно выбранный период отдельно. Порядок строк не используется для угадывания месяцев.

Годовые, месячные и накопительные значения получают разные ключи. Десятичная запятая преобразуется в числовой формат, но исходная строка сохраняется. Неизвестная территория, конфликтующие дубликаты, новый тип периода, несопоставимая единица и резкое снижение охвата останавливают публикацию соответствующего ряда.

Проверка единицы производится по явному измерению, когда оно имеется в метаданных. При его отсутствии сохраняется единица исходного контракта и проверяется название показателя; это ограничение не следует выдавать за независимое подтверждение всех элементов методики.

## Публикация и история

Каждый источник проверяется отдельно. Новые строки добавляются к последнему корректному набору. Изменение существующего числа записывается в provenance как пересмотр. Новый пропуск не удаляет прежнее число. JSON записывается через временный файл и замену, чтобы частично записанный JSON не стал публичным.

Результаты сохраняются в `public/data/latest/`:

| Файл | Содержание |
|---|---|
| `manifest.json` | Общая сводка и состояние каждого источника |
| `data_N.json` | Последний корректный ряд, объединённый с историей |
| `data_N_provenance.json` | Метаданные, выбранные фильтры, роли полей, хеши ответа, новые строки и пересмотры |
| `data_N_raw_sdmx.zip` | Сырые XML-ответы последнего успешного запроса данного источника |
| `catalog_discovery.json` | Каталог, полученный во время проверки, если он доступен |
| `unobserved_discovery.json` | Найденные кандидаты для ранее не наблюдавшихся индикаторов; не автоматическая публикация |

Предыдущие успешные версии этих файлов сохраняются в истории Git после коммитов workflow. Файлы текущей директории не являются полным архивом всех когда-либо полученных XML: старые версии извлекаются из Git. Подробные даты источника имеют приоритет над общей датой проверки.

## Сбои и безопасность

Разрешены только HTTPS и домены из `allowed_hosts`. Проверяются перенаправления. Ограничены таймауты, повторы, размер ответа и частота запросов. Ответ с CAPTCHA или защитной страницей фиксируется как `access_challenge`; обход защиты не реализован.

Опциональный `EMISS_PROXY_URL` читается только из переменной окружения GitHub Secret. В конфигурацию сайта, исходный код и журнал не следует записывать логин/пароль. Используйте только собственный доверенный маршрут доступа, разрешённый правилами источника. Без этого секрета применяется прямое соединение. Добавление HTTPX-прокси не гарантирует доступность ЕМИСС с конкретной площадки.

Сайт не получает этот секрет: браузер читает только публичные JSON. Обновление не принимает URL от посетителя, не исполняет переданный пользователем Python и не загружает код из внешней сети.

## Проверка вручную

```bash
python -m pip install -r scripts/requirements-refresh.txt
python -m unittest discover -s tests -p 'test_*.py' -v
python scripts/refresh_emiss.py --source data_21 --strict
python scripts/update_summary.py
npm test
npm run build
npm run validate
```

Сначала прочитайте manifest и provenance. Затем сравните выбранные территории, период, единицы и несколько значений с официальной страницей показателя. После этого проверьте новый слой в атласе. Включение новых источников должно сопровождаться такой проверкой, особенно при дополнительных измерениях.

Прогноз, кластеризация исходного отчёта, бюджет и содержание нормативных документов не пересчитываются этим скриптом. Обновляется статистический слой, а новые аналитические расчёты выполняются явно в лаборатории.
