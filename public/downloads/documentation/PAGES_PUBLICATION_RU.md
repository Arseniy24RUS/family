# Подготовка публикации GitHub Pages

Накопительная платформа содержит полный каталог `docs/`, исходный `public/` и все исследовательские материалы. По мере расширения полный каталог превысил ограничение размера публикации GitHub Pages. Согласно [официальной документации GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits), опубликованный сайт не должен превышать 1 ГБ.

Выпуск 2.9.0 добавляет самостоятельный этап `npm run build:pages`. После обычных `npm run build` и `npm run validate` он формирует каталог `.pages/`, предназначенный для публикации. Полные `docs/` и `public/` сохраняются. Локальный просмотр через `start_local.bat` и `start_local.sh` использует прежний полный `docs/`.

## Сохранность данных

В выпуске 2.12.0 сжатие применяется к статистическим рядам `data/projects/*/series/*.json` и другим JSON в `data/` размером не менее 64 КиБ. Каталог `downloads/` исключён из преобразования. Каждый исходный JSON без пересериализации помещается в gzip. Числовые литералы, строки, пробелы, флаги качества и происхождение восстанавливаются побайтово. DOCX, PDF, иллюстрации, CSV и остальные скачиваемые файлы сохраняются в обычном виде.

`data/series-transport.json` со схемой `national-projects.series-transport/2` описывает путь, размер и SHA-256 исходного JSON, а также путь, размер и отдельный SHA-256 транспортного gzip. Загрузчик сохраняет совместимость с первым вариантом реестра. По исходному адресу `.json` в компактной публикации находится небольшое описание этого соответствия с явной схемой `national-projects.series-redirect/1`. Полные исходные JSON также входят в накопительный ZIP.

При открытии компактной публикации общий загрузчик приложения читает транспортный реестр. Только для перечисленных адресов своего сайта он запрашивает gzip и возвращает страницам исходный JSON. Остальные запросы не изменяются. При скачивании данных через интерфейс браузер выдаёт исходный JSON с прежним именем. Прямому внешнему клиенту исходный адрес возвращает описание транспортного представления; полный файл указан в поле `compressed_path` и распаковывается обычным gzip.

В статические текстовые страницы подключён тот же небольшой адаптер загрузки. Обработчик клика устанавливается до запроса реестра, поэтому быстрый клик ожидает завершения загрузки. Ошибка допускает повтор. Ссылки на сжатые наборы данных в этих страницах ведут непосредственно на `.json.gz`: при отключённом JavaScript пользователь получает настоящий gzip, при работающем адаптере – распакованный JSON. Относительные адреса сохраняют префикс публикации `/family/`. Библиографические HTML-оригиналы в `downloads/` не переписываются.

Для компактной публикации требуется браузер с поддержкой стандартного `DecompressionStream`. При отсутствии этой возможности приложение сообщает о необходимости обновить браузер либо открыть полный локальный комплект. Обработка ошибки запроса и повреждения gzip сохраняется. Новые серверы, внешние CDN и сервисы хранения не используются.

## Проверки публикационного этапа

Сборщик сравнивает каждый распакованный gzip с исходным JSON, проверяет оба SHA-256, неизменность остальных ресурсов и размер итогового каталога. Для HTML проверяются запланированные изменения адаптера и ссылок. Предел установлен в 1 000 000 000 байт. При превышении размера или несовпадении содержимого сборка завершается ошибкой до замены предыдущего публикационного каталога. Точные размеры текущего выпуска и число проверенных файлов записаны в корневом `PAGES_BUILD_VERIFICATION.json`.

Отдельные тесты проверяют сохранение длинных числовых литералов и кириллицы, отсутствие записи поверх исходных файлов, отказ по размеру и воспроизводимую пересборку. JavaScript-тесты проверяют загрузку с префиксом `/family/`, абсолютные и относительные адреса, Request и AbortSignal, неизменность посторонних запросов, ошибки сети и повреждённого gzip.

Оба существующих workflow — публикация сайта и обновление ЕМИСС — строят `.pages/` после проверки полного `docs/`. Браузерные сценарии в CI направлены на `.pages/`, затем этот же каталог передаётся в GitHub Pages. Расписание, права доступа и версии Actions сохранены. `.pages/` является результатом сборки и не требуется в Git или накопительном ZIP.

## Команды

```bash
npm run build
npm run validate
npm run build:pages
python tests/run_browser.py --directory .pages --output <каталог_проверок_вне_репозитория>
```

Для собственного отчёта о байтах и проверках: `python scripts/build_pages.py --report <путь_вне_каталога_публикации>`. Технический параметр `--link` разрешает жёсткие ссылки для неизменённых файлов при локальной проверке; обычная сборка создаёт самостоятельные копии. Нельзя вручную править сжатый публикационный каталог: изменения вносятся в исходники и проходят повторную сборку.

В `.gitignore` разрешены версионируемые `monitoring/*_last_refresh.json`, которые явно сохраняет workflow обновления. Другие диагностические файлы остаются исключёнными. Проверено фактическим `git add` в изолированном временном репозитории.

Для локальной сборки в среде с ограниченным дисковым пространством доступно `npm run build -- --link-output`. Параметр создаёт жёсткие ссылки для копий исходных ресурсов, сохраняя состав и байты публикации. Обычная команда и CI продолжают создавать самостоятельные копии. При использовании параметра исходники меняют до сборки, после чего повторяют сборку и проверки.
